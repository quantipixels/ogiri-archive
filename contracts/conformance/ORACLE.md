# DTA oracle observations against PROTOCOL rev 2.1

The contract has not been edited. These expectations come from the pinned, unpatched Rails 8.0.5.1 + DTA `b02076a930f7d0a4a155e25feaa7a50b86dbc625` + Devise `05811fb8366edd08874111d0f6fb44543e1c91ef` oracle. `test_http.py` names below reproduce the HTTP observations; the final run counts and commands are in the task report. Rails development API exception responses are empty 500 bodies in this configured reference.

## Source-only qualifications

`token_is_current?` also accepts `previous_token` until the session expires, without consulting batch age (user.rb lines 118-138); only the older `last_token` fallback checks the batch buffer. The rotation suite proves the older-token batch/rejection case, but does not separately claim a live proof of this immediate-previous-token edge.

The H1/H3 long-client request uses an unknown 65-character client. It proves rejection of that request; it does not establish a separate DTA length guard for an artificially seeded valid overlength client. The Ogiri schema limits stored clients to 64 characters.

S2's unknown-email timing equivalence is not measured. DTA's explicit dummy password hash is conditional on paranoid mode (sessions_controller.rb). HTTP assertions cannot prove lookup constant time or CSPRNG strength.

T2's independent-connection checks establish visibility and database-clock plausibility, not the surrounding-application-transaction/startup-DDL guarantees. Those need implementation or instrumented checks.

## Intentional exclusions and corrected hypotheses

D-R, D-Q and D-S are explicitly marked Ogiri-only and skipped with reasons against the reference. Added D1-D3 device routes and T2 separate-store checks are also reference skips. O1 is a documented OAuth skip; no fake provider is supplied. These exclusions must not be mistaken for passed DTA behavior.

The initial suspicion that P3 stores the raw reset token was disproved: the database digest remains distinct from the emailed raw token after following the link. `test_E1_email_tokens_and_config` checks that, and strict proves raw confirmation storage versus digested unlock storage.

AC2 uses two real Rails processes sharing PostgreSQL. Cross-language AC2 remains for the library builders. AC3 uses published vanilla-token-auth 1.0.6; current active maintenance could not be established, as documented in README. No JS auth method is mocked.
